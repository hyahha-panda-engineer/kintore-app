# Git コミット・運用ルール

本プロジェクトにおける AI エージェントの Git 操作・コミットルールです。

---

## 1. コミットのタイミング (必須)

エージェントがコード、ドキュメント、設定ファイル等の変更を行った際は、作業単位・論理的な区切りごとに**必ず Git コミットを作成**してください。
変更をコミットせずに放置してターンを終えてはいけません。

---

## 2. コミット前確認手順

1. `git status` および `git diff` で変更内容を確認する。
2. 意図しないファイル（一時ファイルや `.gitignore` 対象の `memo.txt` など）が含まれていないことを確認する。
3. `git add <ファイル名>` でステージングする。
4. 適切なプレフィックスを付けたコミットメッセージで `git commit -m "..."` を実行する。

---

## 3. コミットメッセージの形式

Conventional Commits に準拠したプレフィックス + 簡潔で分かりやすい日本語サマリーとします。

- `feat: <新機能追加>` (例: `feat: 種目の並び替え機能を追加`)
- `fix: <バグ・不具合修正>` (例: `fix: 日付変更時に履歴が正しく再描画されない不具合を修正`)
- `docs: <ドキュメント整備>` (例: `docs: 設計メモおよびエージェント運用ルールを追加`)
- `style: <UI・デザイン調整>` (例: `style: ボタンのタップ領域とコントラストを調整`)
- `refactor: <リファクタリング>` (例: `refactor: GAS通信部分の共通処理を関数化`)

---

## 4. push の扱い (慎重対応)

- `master` ブランチへの `git push` は **GitHub Actions がトリガーされ、本番環境 (GitHub Pages) に即座に自動デプロイ**されます。
- そのため、原則としてローカルでの `commit` までをエージェントが責任を持って行い、リモートへの `push` はユーザーの明示的な指示・承認を得てから実行してください。
